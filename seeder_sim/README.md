# 电控播种机下位机模拟器 (seeder_sim)

用 Python 完全复刻 `hd3005a2`（最新 6 行机固件，4 行机兼容老版 `hd3005a1` 行为）与 QT 上位机 (`AgricultureMachine/SowSystem`)
之间的串口通信行为，支持 **4 行机 / 6 行机**，可在不接真实播种机的情况下联调上位机。
提供**图形界面**（连接管理、实时状态、工况控制、收发帧/调试信息查看与导出），
联调出问题时可一键导出收发帧和调试信息用于排查。

已在本机 ELTIMA 虚拟串口对 (COM8↔COM9) 上做过 25 项端到端联测，全部通过，
覆盖心跳连接、参数读写、AB 线、小区播种全流程、测试模式、连续播种与静默规则。

## 1. 环境与启动

依赖：Python 3.8+，`pip install pyserial PySide6`

```
python gui.py                       # 图形界面 (推荐)
python main.py --gui                # 同上
python main.py --list               # 列出可用串口
python main.py --port COM8          # 终端模式 (后台/脚本场景), 默认4行机
python main.py --selftest           # 自测: CRC/结构体/帧/状态机
```

## 2. 图形界面

- **顶部**：串口选择/刷新、行数(4/6，会随上位机 0x25 自动切换)、行进速度、
  收发帧记录开关、连接/断开。
- **左侧 工况控制**：暂停/继续行进、北斗丢失/恢复、行驶反向、零位故障注入、
  一键初始化、行程开关触发——对应原终端命令，用于测试上位机的各种异常显示。
- **右侧 三个页签**：
  - **收发帧**：实时帧列表（时间/方向/功能码/长度/摘要，悬停看完整 HEX），
    支持收/发过滤、**导出收发帧…**、复制选中帧 HEX；
  - **调试信息**：调试字符串与状态变化时间线，**导出调试信息…**；
  - **运行日志**：模拟器自身日志。
- **底部 实时状态**：0x21 视角的工作模式/RunState(红停止/黄准备/绿播种)/行号/
  行程/速度/垂直偏差/漏种漏肥计数/当前调试信息。

## 3. 联调排障：导出联调信息

出现通信问题时，把两个导出文件发回即可复现分析：

- 「收发帧」页签 → **导出收发帧…**：`seeder_frames_时间戳.txt`，
  含会话信息(串口/行数/版本)、每帧完整 HEX 与解码摘要；
- 「调试信息」页签 → **导出调试信息…**：`seeder_debug_时间戳.txt`，
  含调试字符串与状态机变化的时间线。

导出文件示例（UTF-8 带 BOM，记事本/Excel 可直接打开）：

```
[09:09:44.991] 收 上位机->模拟器 0x20 SET_BZ_PARA len=92
  HEX  68 20 5C 00 01 00 ...
  摘要  方向=同向 行号=1->2 行长=2000cm 过道=100cm 起点=0cm 密度=5000/5000/5000/5000/0/0
[09:09:45.816] 调试  预充种-预落种[1]
[09:09:45.816] 状态  模式=小区播种 RunState=运行 阶段=预充种-倒种 北斗=正常 行进=正常
```

终端模式也可导出：`python main.py --port COM8 --export-frames 帧.txt --export-debug 调试.txt`，
退出时自动落盘。

## 4. 与上位机联调

上位机只认真实串口 (QSerialPort)，需要一对互通的虚拟串口
(本机已装 ELTIMA VSPD，现有对 COM8↔COM9；用 com0com 亦可)：

1. 启动模拟器占用一端：`python gui.py`，界面上选择 `COM8` → 连接
2. 上位机 `config.ini` 中 `[Application] SerialPort` 改为另一端 `COM9`
   (或在上位机"设置"页面选择串口)
3. 启动上位机。其每 500ms 发一次 0xA3 心跳，模拟器应答版本串
   `hd3005a2_sim v1.7 20260820_2,vol:12.1`，即显示"已连接"。

**4 行机 / 6 行机**：上位机由 `config.ini [Device] DeviceType`("4行机"/"6行机")决定
界面列数，并在进入各模式前通过 0x25 厂家参数**偏移 23 的 U8Resv2 字节**把行数(4/6)
下发给下位机——模拟器收到后自动切换（界面行数框会跟着变）。

不启动 QT 程序快速验证环境：`python test_uc_flow.py --port COM9`
(扮演上位机跑完整流程)。

## 5. 终端模式命令（`python main.py --port COM8`）

```
help / stat / para / ab     查看状态、参数、AB线
speed <mm/s>                行进速度 (默认1000=1m/s)
rows <4|6>                  强制切换行数
pause / resume              暂停/恢复行进 (Speed上报0)
bd off|on                   北斗信号丢失/恢复 -> "无法获取定位信息"、BdState=0
reverse on|off              实际行驶方向与下发相反 -> "下发方向与实际行驶方向不符"
zerofail on|off             零位开关故障 -> "零位开关触发错误"
init                        模拟按下一键初始化按钮 (测试模式回零流程)
trigger                     模拟北斗行程开关触发 (BdCnt+1, 无A点时记录A点)
hex on|off                  原始帧十六进制打印
quit                        退出
```

## 6. 文件结构

| 文件 | 职责 |
|---|---|
| `gui.py` | 图形界面 (PySide6)：连接、状态、工况控制、帧/调试查看与导出 |
| `recorder.py` | 收发帧/调试事件记录、导出文件、帧摘要解码 |
| `main.py` | 串口收发线程、帧分发 (对齐 protocol.c FrameProcess)、终端模式、自测 |
| `protocol.py` | 帧构造/增量解析、Kermit CRC16 查表、功能码定义 |
| `layout.py` | 全部协议结构体 pack/unpack，尺寸与上位机 protocol.h 一致 |
| `device.py` | 厂家/用户/AB线参数、合法化检查、JSON 持久化 (模拟EEPROM)、行数 |
| `workproc.py` | 工作状态机 (空闲/小区播种/连续播种/测试)、北斗行程模拟、计数合成 |

| `test_uc_flow.py` | 端到端联测脚本 (扮演上位机) |

## 7. 协议要点 (从两端源码逆向并对齐)

- 帧格式：`0x68 | FNC(1B) | len(2B小端) | data | CRC16(2B小端) | 0x0D`，
  CRC 为标准 CRC-16/KERMIT (反射 0x8408 查表、初值 0、无异或)，
  校验范围为帧头至数据域末尾。串口 115200-8N1。
- 纯请求/应答，下位机不主动上报；0xA3 心跳应答版本串(带 NUL)。
- ACK：1 字节 0x01 成功 / 0x00 失败；数据域长度不符回 0x00；
  getter (0x04/0x08/0x21/0x22/0x26/0x28/0xA3) 带数据则静默；0x30/0x32 固件未实现，静默。
- 0x22 调试信息为 GB2312 编码、无 NUL。
- 参数合法化 (0x25/0x27 后)：GearRatio<2→10、HoleNum=0→9、HJ<10或>5000→60、
  DZTime<100或>10000→1500、Rpm<5或>70→20、TapperTime>1000→60、
  MicroStepValue>6400→800、EncodeNum=0→700；连续播种参数
  Density<100→1000、Hju<5→60、CellLen<10→500。

## 8. 行为模型 (对齐固件 BD_SIMU_TEST 构建的模拟量)

- 启动小区播种 (0x0A)：行号上报 `-10000000` 保持 600ms，随后起始行程取
  `StartPOS∓800cm`；恒速 `BdSimuSpeed` 沿 AB 线行进。
  垂直偏差模型：初始 = -(行数×行距)（4行×60cm=-240，6行×60cm=-360），
  每次启动 += 行数×行距——即第 1 排压在 AB 线上（垂直偏差 0），
  以后每掉头一次增加一个作业幅宽；点击**一键初始化**会把垂直偏差复位为
  -(行数×行距)，相当于机器重新对准 AB 线准备首排，下次启动后回到 0。
  停止时行程/垂直偏移上报 0。
  (固件测试代码硬编码 -481/+240 为无物理含义的测试值，模拟器按行数/行距计算。)
- 0x21 的 RunState 字节：0=停止(红)、1=准备(黄)、0x81=行进播种(绿)。
- 状态机：等待零位(ZeroPosEn)→预充种(清种/预落种/倒种)→播种盘调整→等待开始播种
  →等待清种/刮种/换排循环；换排条件为行程越过
  `StartPOS+CellLen+InS+(A-B)`，执行 Next→Curr 晋升并清零漏种/漏肥计数；
  上位机未及时下发后续小区则报"播种结束[%d]"并进入异常等待。
- 漏种/漏肥计数按 `速度/株距` 合成，株数=ceil(密度×行距×行长/666.67)，株距=行长/(株数-1)；
  换排时清零，与固件一致。**任务结果的数值语义**（上位机侧，`dialogrealtimetask.cpp:441`）：
  上位机每 200ms 轮询都用 0x21 的实时计数刷新"当前排"的结果，因此每排最终记录 =
  该排窗口内**最后一次被刷新时**的实时计数——正常播种排接近满值；地图上不播种的排
  刷新会被 `isSow` 跳过，只停留在换排初期写入的 0~1；停止时正在播的排为部分值。
- 测试模式：0x09 的 CtrlNo 0~9 映射阀门位；电机位与上位机固定映射一致：
  **16-19=播种盘1-4，20=自动供种电机(4/6行机相同)，21/22=播种盘5/6(仅6行机)**。
  漏种/漏肥计数**按路跟随对应的播种盘电机**（开哪路盘哪路计数），
  仅开供种电机不产生计数。倒种/预落种在 DZTime 后自动关闭，打点器在 TapperTime 后自动关闭。
- 零位开关：播种盘的相位零点，用于启动时各盘对齐(厂家参数 ZeroPosEn=1 时)
  与测试模式一键初始化回零。注入"零位故障"后：开关输入位清零、对应 WarningState
  报警位置 1(上位机测试页显示红色报警/声光)、回零序列转一圈后报
  "零位开关触发错误"。注：真机固件把 WarningState 硬编码为 0(未实现上报)，
  报警位是模拟器的扩展，便于验证上位机报警界面。

## 9. 与两端源码版本的对应关系 (重要)

模拟器**以 hd3005a2（最新 6 行机固件）为基准**，默认 6 行机、版本串
`hd3005a2_sim v1.7 20260820_2`：

- hd3005a2 的结构体：BZCellParaType=92B(Density[6])、BZStatusType=**84B**
  (`Resv2[8-(LINE_NUM-4)*2]`=Resv2[4])、TestModeStateType=68B、其余尺寸不变。
  0x21 应答 84B 中**常用字段偏移与上位机 protocol.h(Resv2[8],100B) 完全一致**，
  上位机按 sizeof memcpy 超读的部分仅是未使用的 Resv2，与真机行为一致。
- 行数：hd3005a2 为编译期 `LINE_NUM 6`，厂家参数偏移 23 的行数字段固件**不读取**；
  模拟器把它用作运行时切换（4 行模式≈老版 hd3005a1 行为），方便配合上位机
  4行机/6行机两种配置联调。
- `BD_SIMU_TEST=0`（hd3005a2 走真实北斗）：模拟器以合成行进（恒速沿 AB 线）
  代替真实 NMEA，状态机走真实固件路径（等行程开关记 A 点、方向判定等）。
- **复刻的 hd3005a2 原生行为/缺陷**（真机同样如此）：
  - `ClearLzCnt` **已修复**：固件 `para.c` 循环上界由 4 改为 `LINE_NUM`（20260917），
    模拟器同步清零全部 6 路漏种/漏肥计数；
  - `UpdateRowNumCheck` 的密度 `memcpy` **已修复**：固件由 16 字节改为
    `sizeof(...)` 全 6 路拷贝（20260917），换排后 5/6 路密度正常更新，模拟器同步；
  - 测试状态 `EncoderCnt` 恒为 0（编码器硬件已删除）；
  - CtrlNo 16-19=播种盘1-4、20=自动供种、21/22=播种盘5/6，MAX_CTRL_NUMS=23，
    播种盘掩码 0x6F；测试模式一键初始化旋转半圈后等零位。

## 10. 已知简化

- 电机以"脉冲目标+转速"抽象建模，只复现各阶段耗时与对外可见状态，不模拟细分脉冲波形。
- 0xA0/0xA1 升级命令直接 ACK 成功但不落盘，0xA2 因 CRC 必然不符回 0x00
  (模拟器无固件可升级)。
- 北斗定位不解析真实 NMEA，A/B 点经纬度为合成值 (36.40N, 117.00E 附近)。
